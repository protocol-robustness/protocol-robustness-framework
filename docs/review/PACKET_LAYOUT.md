# EF review packet layout

This packet is a self-contained technical-review artifact. Everything a reviewer
needs — the reviewed binary, its inputs, the generated evidence, the assurance
documentation, and the read-only verifier — is inside the packet directory.

The packet is **self-hosting**: the packaged jar computes its own canonical
`sha256:<hex>` references, and the packaged `bin/verify-review-packet.sh`
revalidates the whole packet using only the packet contents.

All root-relative references below are relative to the packet directory.

## Entry points

| Path | Meaning |
|---|---|
| `REVIEW_PACKET_MANIFEST.json` | Machine-readable manifest. Begin here. Lists the reviewed jar, its sha256, provenance reference, each evidence profile, reference vectors, and every example (input → evidence bundle → semantic outcome → verify command). |
| `PROVENANCE.txt` | Packet provenance: schema version, built jar path, build timestamp (UTC), repository VCS + commit, and the jar's sha256. |
| `SHA256SUMS` | Canonical `sha256:<hex>` reference list for every packaged file, emitted by the packaged jar itself (`ref-file`). |

## Top-level directories

| Directory | Meaning |
|---|---|
| `bin/` | The reviewed artifact and the self-contained verifier. |
| `docs/` | Assurance and review documentation. |
| `inputs/` | Immutable inputs for review. These are **not** generated by the packet; they are the files a reviewer re-runs or cross-checks. |
| `evidence/` | Freshly generated, independently verified evidence bundles (one subdirectory per example). |
| `diagnostics/` | Derived reviewer aids. Outside the immutable evidence bundles; their generation cannot alter any commitment. |

## `bin/`

| Path | Meaning |
|---|---|
| `bin/prf-runner-sew-0.1.0-uber.jar` | The reviewed binary (source-only uberjar, `clojure.main` as `Main-Class`). Run it with `-m resolver-sim.cli.main` for the CLI. |
| `bin/verify-review-packet.sh` | Self-contained packet verifier. From inside the packet: `bash bin/verify-review-packet.sh .` Revalidates canonical refs and every evidence bundle. |

## `docs/`

| Path | Meaning |
|---|---|
| `docs/REVIEW_GUIDE.md` | Primary review guide: scope, evidence architecture, what each example establishes, limits, and inspection procedure. |
| `docs/SCENARIO_REVIEW_HIGHLIGHTS.md` | Concise, derived review priorities (claims, custody, finality, value-at-risk). Derived summaries are **not** authoritative evidence. |
| `docs/BENCHMARK_ASSURANCE_SPEC_V1.md` | Benchmark assurance contract: what a benchmark evidence bundle asserts and how it is verified. |
| `docs/specs/SEW_CUSTODY_EXPOSURE_V1.md` | Custody-at-settlement-deadline evidence profile spec instantiated by the force-authorisation benchmark. |
| `docs/PACKET_LAYOUT.md` | This file. |

## `inputs/`

Immutable review inputs. Their sha256 references are committed in
`REVIEW_PACKET_MANIFEST.json` and `SHA256SUMS`.

| Path | Meaning |
|---|---|
| `inputs/scenarios/*.edn` | Scenario definitions (EDN). One per example plus additional reference scenarios. The examples replayed are the three scenarios under `evidence/scenario-*`. |
| `inputs/benchmarks/force-authorisation-custody-v1.edn` | Benchmark definition for the force-authorisation custody example. |
| `inputs/test-vectors/pro-rata/*.json` | Independent deterministic calculator reference vectors for pro-rata allocation (insufficient-liquidity, equal-buckets-dust). They are **not** replay witnesses for `Y06`; they are standalone calculator references. |

## `evidence/`

Generated, immutable evidence bundles. Each subdirectory is a completed,
independently verifiable run:

| Directory | Example | Semantic outcome |
|---|---|---|
| `evidence/scenario-rejected/` | `S-DR-084` late evidence rejected | pass |
| `evidence/scenario-pro-rata/` | `Y06` multi-party pro-rata shortfall | pass |
| `evidence/scenario-semantic-failure/` | `S-NC-001` freeze during active dispute | fail (expected, unsuppressed invariant violation) |
| `evidence/benchmark-force-authorisation/` | `force-authorisation-custody-v1` | benchmark (inconclusive conclusion) |

Each bundle is verified with `verify-scenario --run-root <dir>` or
`verify-benchmark --run-root <dir>`.

### Scenario bundle layout (`evidence/scenario-*/`)

| Path | Meaning |
|---|---|
| `completion.json` | Terminal lifecycle seal: lifecycle completed, semantic outcome, and committed references to finalization, package index, artifact registry, and validation. **Completed does not mean passed.** |
| `manifest/` | Outer manifest and assurance surface for the run. |

| `manifest/summary.json` | Concise execution summary including the value-at-risk overview. |
| `manifest/diagnostic-summary.json` | Reviewer-facing diagnostic projection: `scenario_id`, semantic outcome, evidence refs, and primary diagnostic (for failures). |
| `manifest/artifacts.json` | **The authoritative file inventory** for the bundle (path → sha256 → role). |
| `manifest/artifact-registry-validation.json` | Validation result of `artifacts.json`. |
| `manifest/canonical-integrity.json` | Unsigned canonical-integrity assurance binding finalization, content registry, and validation. |
| `manifest/forensic-claims-status.json` | Forensic/forensic-claims status (deferred when no signing configured). |
| `manifest/verdict-policy.json` | Verdict-policy artifact binding the semantic outcome to its immutable inputs. |
| `manifest/run-package-index.json` | Package index: every bundle artifact with ref and sha256. |
| `manifest/value-at-risk.json` | Value-at-risk projection (declaration-driven observation artifact). |
| `manifest/value-at-risk-timeline.json` | Value-at-risk timeline projection. |
| `manifest/claimable-classification.json` | Claimable fund classification. |
| `manifest/run-enrichment.json` | Run enrichment record. |
| `manifest/sensitivity-report.json` | Sensitivity profile of the run. |
| `evidence/` | Content-addressed evidence. |
| `evidence/content-registry.json` | Content registry: every file in the bundle with sha256 and role, plus its `content_root`. |
| `evidence/finalizations/run/evidence-finalization.json` | Run-level evidence finalization (terminal commitment). |
| `evidence/reports/run-evidence-reconciliation.json` | Reconciliation report tying scenario finalizations to the run finalization. |

| `inputs/scenarios/<hash>-<name>.edn` | Content-addressed snapshot of the scenario input actually run. |
| `scenarios/<slug>/` | Per-scenario execution tree (one subdirectory). |
| `scenarios/<slug>/execution/` | Execution artifacts: `execution-dag.json` (execution DAG), `pre-run-commitment.json`, `replay-output.json` (the persisted `bundle-root.v2`), `runner-finalization.json`. |

| `scenarios/<slug>/summaries/` | Reviewer summaries: `trace-summary.json`, `metrics.json`, `claimable-classification.json`, `mechanism-summary.json`, `schema-map.json`, `trace-plain.md`. |
| `scenarios/<slug>/state/world-final.json` | Final world state (redacted for public profile). |

## How the pieces relate

1. `inputs/` are the seeds; their hashes are committed in the manifest.
2. The packaged jar replays the inputs into `evidence/` bundles.
3. Each bundle's `manifest/artifacts.json` is the authoritative inventory; the
   jar recomputes and validates every committed hash.
4. `bin/verify-review-packet.sh` verifies the whole packet: canonical refs
   (`SHA256SUMS`) and every scenario/benchmark bundle.
5. `completion.json` only attests lifecycle completion — scenario/benchmark
   outcomes (pass/fail/inconclusive) are recorded separately and reported in
   `REVIEW_PACKET_MANIFEST.json`.
