# Screenshot Export for Notebooks

## 1. Goal

Produce browser-accurate screenshots of Clerk notebooks for review, presentation, and
documentation. Two complementary modes:

- **Full-page** — one tall image of the entire notebook (`full.png`).
- **Per-section** — one viewport image per markdown section, driven by the notebook's
  headings (`01-<slug>.png`, `02-<slug>.png`, …).

Both modes are configurable per notebook. The default is **full-page per notebook**
(cheap, safe); long narrative notebooks opt into per-section shots.

The screenshots are generated by a headless browser (Playwright, already installed)
against the **live Clerk server** so the pixels match what a human sees.

## 2. Architecture

```
┌────────────┐  navigate  ┌──────────────┐  screenshot  ┌─────────────┐
│ bb task     │ ─────────▶ │  Clerk server │ ───────────▶ │ shots/      │
│ (orchestr.) │   :7777    │  (serve.clj)  │              │  contact +  │
└────────────┘            └──────────────┘              │  PNGs       │
        │                                                  └─────────────┘
        │ reads data/notebook-shots.edn
        └▶ python3 scripts/export_notebook_shots.py
             · playwright.sync_api · chromium headless
```

- **Driver**: `scripts/export_notebook_shots.py` (Python Playwright). Pure CLI, no repo
  deps — matches the existing `scripts/evidence/*.py` convention.
- **Target**: the Clerk server started by `bb notebook` (`src/notebooks/serve.clj`, port
  7777), which already pre-evaluates every notebook so each is reachable by URL.
  The task reuses a running server if present, else starts one.
- **Config**: `data/notebook-shots.edn` (see §5). Notebook set defaults to the non-archived
  entries in `data/notebooks.edn` (the hub registry), so the export always covers the hub.

## 3. Pipeline (per notebook)

1. Resolve the notebook list from config (or registry).
2. Launch headless Chromium once and reuse the browser across notebooks:
   `viewport 1440×900`, `device_scale_factor 2`, `hide_scrollbars True`, dark-mode on.
3. Navigate to `http://localhost:7777/notebooks/<name>`.
4. **Wait for render** — Clerk evaluates over a websocket; capture only after the DOM is
   settled:
   - wait for Clerk's root container `.notebook-viewer` to appear, then
   - poll until the count of `.viewer` blocks is stable (proves evaluation finished), then
   - wait `settle-ms` (default 1500 ms) for fonts, tables, and charts to lay out, and
   - wait for network idle + `document.fonts.ready`.
   - Abort after `timeout-ms` (default 60 s); record the notebook as failed.
5. **Capture**:
   - `full` → `page.screenshot(full_page=True)`.
   - `sections` → each section is captured at its **full extent** (from its heading
     to the next heading), not just the first viewport. The viewport is temporarily
     resized to the section's height, the heading is scrolled to the top, and the
     section is clipped in one shot — so a section taller than one screen is captured
     whole. Sections taller than `MAX_VIEWPORT_H` (16000 px) are clipped with a note
     (full stitching would need PIL). Filename = `NN-<slug>.png`.
   - `:section-viewport true` (config) restores the old behaviour: one viewport
     screenshot per heading instead of the full section.
6. Write to `shots/<name>/…` (staging), then apply the final layout rule (§4). Re-runs
   clean a notebook's prior outputs first, so the export never accumulates stale files.
7. After the run, regenerate the contact sheet (see §4).

Per-notebook failures are caught, logged, and skipped; the run exits non-zero if any fail.

## 4. Output layout

Screenshots are easy to find after a bulk export by a simple, predictable rule
(this was the explicit requirement):

- **Single-shot notebook** → `shots/<name>.png` (flat file named after the notebook).
- **Multi-shot notebook** → `shots/<name>/full.png`, `shots/<name>/01-<slug>.png`, …,
  one directory per notebook.

```
shots/
  index.html                 # contact sheet: thumbnails → each image
  report.png                 # single-shot notebook (full-page only)
  report/01-adverse-escrow-lifecycle.png   # multi-shot notebook
  report/02-resolution-throughput.png
  demo_short_circuit/
    full.png
    01-short-circuit-execution-composition-demo.png
    ...
  run-meta.json              # base url, settings, ok/failed lists
```

- `index.html` is a single self-contained contact sheet referencing the PNGs relative to
  `shots/`, so it opens locally or copies anywhere as a set.
- `run-meta.json` records the base URL, settings, and per-notebook `ok`/`failed` lists so a
  reviewer knows which run a shot came from.
- `shots/` is gitignored (generated artifacts). Re-running a notebook replaces its prior
  outputs, so the tree never accumulates stale shots.

## 5. Config schema — `data/notebook-shots.edn`

```clojure
{:output "shots"
 :viewport   {:width 1440 :height 900}
 :device-scale-factor 2
 :section-level 2        ; screenshot per heading at this level and below (h1..h3)
 :settle-ms   1500
 :timeout-ms  60000
 :default     {:modes [:full]}                    ; fallback when a notebook has no override
 :notebooks
 [{:path "notebooks/report.clj"  :modes [:sections] :section-level 2}
  {:path "notebooks/demo_short_circuit.clj" :modes [:full :sections]}
  {:path "notebooks/evidence_graph_viewer.clj" :modes [:full] :interactive true}]
 :exclude ["notebooks/_template.clj"]}
```

- `:modes` ∈ `[:full :sections]`. Absent → `:default`.
- `:interactive true` marks workbench-style notebooks whose static shot captures only the
  initial state (see §6 caveats); recorded in `run-meta.edn`, not a hard failure.
- `:exclude` skips non-notebook support files (`util/`, `_template`).

## 6. Determinism, correctness, and caveats

- **Stable capture**: fixed viewport, DPR, and hidden scrollbars keep dimensions constant
  across runs.
- **Dark mode**: notebooks set `:dark-mode true`; Clerk toggles a class on `<html>`.
  The driver verifies the computed body background is dark (not white) before capture and
  records a warning otherwise.
- **Content is deterministic**: report/golden artifacts are pinned; stochastic Monte Carlo
  notebooks are excluded from `:sections` by default in the shipped config.
- **Interactive viewers** (`evidence_graph_viewer`, `workbench_v2`, `telemetry`,
  `xtdb_overview`) are captured as initial state only. A scripted-interaction mode is a
  future extension; it is out of scope for v1.
- **Emoji/fonts**: rendering depends on installed system fonts; emoji may fall back. Note
  in `run-meta.edn` if `fc-match` reports missing fonts.
- **Very long notebooks** (`report.clj`, `not_admitted.clj`) produce very tall full-page
  PNGs; prefer `:sections` for those. `:sections` now captures each section's full extent
  (not one screen); opt back to one-screen-per-heading with `:section-viewport true`.
- **Disk space**: screenshots are large (DPR 2, tall full-page images). Ensure free disk
  before a bulk export; `not_admitted` with `:sections` can emit many tens of MB.
- Screenshots are evidence of **rendering**, not of correctness — keep `bb notebook:ci`
  as the correctness gate.

## 7. CLI / bb tasks

```shell
bb notebook:shots          # full run from data/notebook-shots.edn into shots/
bb notebook:shots:one report   # single notebook (name without .clj)
bb notebook:shots:sections report  # force per-section mode for one notebook
bb notebook:shots:open     # open shots/index.html
bb notebook:shots:setup    # one-time: python3 -m playwright install chromium
bb notebook:shots:ci       # render gate: full-page shots for all notebooks (target/shots-ci)
```

`scripts/export_notebook_shots.sh` is the entry point behind all of them: it ensures the
Clerk server is up (reusing one on :7777, else starting it and waiting), then runs
`scripts/export_notebook_shots.py`. Pure logic lives in `scripts/notebook_shots_util.py`
(EDN config, slugify, path layout) and is covered by `scripts/test_notebook_shots.py`.

`notebook:shots:ci` renders every hub notebook full-page into `target/shots-ci` (gitignored
via `**/target`) and fails on any render error — a cheap rendering regression gate that
complements `notebook:ci`.

## 8. Implementation

Shipped (this feature):

- `scripts/export_notebook_shots.sh` — server-ensure + run.
- `scripts/export_notebook_shots.py` — Playwright driver (CLI).
- `scripts/notebook_shots_util.py` — pure helpers (EDN config, slugify, path layout, JS).
- `scripts/test_notebook_shots.py` — unit tests for the pure logic.
- `data/notebook-shots.edn` — config.
- `bb.edn` tasks (`notebook:shots`, `:one`, `:sections`, `:open`, `:setup`, `:ci`).
- `shots/` gitignored.

## 9. Resolved / open decisions

Resolved during implementation:
- **Default mode** `[:full]`; curated `:sections` for narrative notebooks in the config.
- **Output location** `shots/`, gitignored; contact sheet is the entry point.
- **Single fixed viewport** 1440×900 @ DPR 2 for all modes.
- **Readiness** is `.notebook-viewer` present + `.viewer` count stable (not `<article>`).
- **Re-runs replace** a notebook's prior outputs (no stale accumulation).

Still optional / future work:
- `:interactive` notebooks captured as initial state only; a scripted-interaction mode is
  out of scope.
- Emoji/fonts depend on installed system fonts.
- A `--only-failures` rerun exists in the CLI; `:pr` (changed-notebooks) is not wired as a
  bb task yet.
- Very long notebooks produce very tall full-page PNGs; prefer `:sections` for those.
- Screenshots are evidence of rendering, not correctness — keep `bb notebook:ci` as the
  correctness gate.
